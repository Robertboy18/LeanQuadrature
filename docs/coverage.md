# Paper coverage

This ledger compares our proofs with Andrew W. Appel and David S. Bindel's
*Formalization of Gaussian Quadrature and Application Verification (Preliminary Draft)*.
The [source review](../evidence/upstream-review.json) identifies the manuscript
and code examined. Rows describe the current results and their hypotheses.
The [current Lean build and assumption audit](../evidence/lean-quality.json)
covers every local project module listed here. The general Gaussian theory,
explicit Legendre rules, and root and weight certificate proofs were
developed here and moved into LeanPDE; rows under
`PDE/Symbolic/Continuum/Quadrature/` now refer to imported dependency proofs.
Their ownership is separate from the local module and theorem counts.

**Shared open boundaries.** The C-source proofs cover all evaluation orders in
our adaptation of CompCert's C small-step semantics. Behavioral preservation to
the actual Clight frontend output is proved for the selected library calls.
General parser/elaborator correctness, including static-array hoisting from an
independent source semantics and preprocessing, and correspondence with Rocq's
semantics remain open. The library result does not cover native execution or
printing. The authored Clight applications and imported assembly report the
same binary64 values that the initialized C library returns. This proved
agreement does not establish that compiling the original C text produces
those assembly trees.
The original external-call variant still needs a platform-cosine
contract; the polynomial C library has no such assumption. Infinite-interval
quadrature is outside the mathematical development.

Csharpminor and Cminor. `SilentTermination.v` proves that a finite silent
execution in a determinate semantics determines every competing prefix.
`CminorSafety.v` uses it to prove total correctness of the four compiled library
calls; `CminorIntegralAccuracy.v` gives the same integral-error budget for every
return. Final memory is related to initial source memory by injection.
An added Clight application entry initializes the library,
emits `quadrature-result` with the example's binary64 value, and exits with status
zero; this is the unique program behavior in both Clight and Cminor.
The annotation is an event in CompCert semantics. It is not a verified `printf`
call, and the authored entry has no C-parser correspondence theorem.
The remaining backend simulations are composed. The reusable release-compiler
theorem is conditional on successful compilation; `CertifiedExternal.v`
discharges that premise for a separately configured compiler.
The real-integral identity and concrete result's error bound are also proved
in Rocq. The resulting assembly accuracy theorem retains the two external
cosine contracts. The platform `libm` and a general correspondence for finite
FloatLib–CompCert arithmetic remain unverified. Unrestricted bitwise agreement
is false: the libraries use different NaN policies. The paired certificates
and the finite domain needed by the quadrature proof are explained in
[the model correspondence note](float-models.md).

The separate polynomial application removes the external cosine premises by
using an internally proved Clight routine. Its source and Cminor accuracy
theorems have no cosine-call hypotheses. `CertifiedPolynomial.v` supplies
the concrete assembly witness and removes the backend success premise too.
The original variant certifies the polynomial outputs at the two example inputs.
The stored-order variant certifies the complete computations for orders 1–10,
with matching independent FloatLib results and integral bounds. The original
four-order interface remains available.
The original library-cosine application retains its external contracts.
All four certificate files use the explicit compiler variant in
[`compcert/certification`](../compcert/certification/README.md): concrete
oracle choices, kernel-validated allocation candidates, a bounded iterator,
and proved computational paths for graph and union-find operations.
The full compiler proof is checked again after these changes.

All listed Lean project theorems are checked by Lean. `scripts/Audit.lean` traverses
their transitive axiom dependencies and rejects anything except `propext`,
`Classical.choice`, and `Quot.sound`. It also rejects project axiom declarations,
including unused ones. The current theorem count includes declarations generated
by Lean for the project's definitions. There are no admitted project proofs.
`evidence/lean-quality.json` records that count and the source, configuration,
build-log, and audit-log hashes for the latest check.

The existing quadrature Clight execution proof is checked separately by Rocq. `scripts/check-clight.py` checks
the pinned source hash, rebuilds the proof, and rejects assumptions outside
its explicit CompCert/Flocq allowlist. The two cosine contracts are visible
arguments of the theorem, not discharged facts. Its assumptions and source hashes
are recorded in `evidence/clight-proof.json`; [the compilation note](compilation.md)
explains the distinct checker and architecture boundaries.
The release-compiler backend theorem additionally uses CompCert's computational parameters,
including compiler options and untrusted oracle outputs whose use is guarded by
verified validators. These are listed separately in the evidence. Successful
compilation remains a visible theorem premise.

The configured compiler audit is recorded separately in

compiler-choice parameters and no successful-compilation hypothesis.
They still depend on the explicitly listed standard logical and

generated parser, configuration, project proofs, and check logs are identified
by hashes; no prebuilt compiler proof objects are imported into this build.

`scripts/check-clight-roundoff.py` separately rebuilds ten general numerical

and integral theorems. The combined 27-file, 210-audit record is
`evidence/clight-integral.json`. The assumption
allowlist is unchanged. See `compcert/analysis/README.md` for the dependency
versions and their observed compiler compatibility.
